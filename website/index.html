1. Problem and users

Students search for lost items; centre staff maintain the catalogue. Campus Find returns up to three possible matches with descriptions, found places and optional photos.

The initial 30 examples are fictional. Authorised staff can add records and confirm an in-person handover to remove a collected item and its photo.

2. How it works

  1. Input: an English item description (up to 300 characters), a search method and optional category/place filters.
  2. Processing: validate input, load SQL records and rank candidates using keyword overlap or the configured AI model. AI responses are checked against catalogue IDs and exact source excerpts.
  3. Output: up to three matches with original descriptions, or a no-match, clarification or error message.

Students have read-only search and browsing. Staff sign in with a separate app account. Keyword search works now; AI matching still needs a provider key.

3. Implementation

Project work: student/staff interfaces, SQL records and photos, account permissions, collection transactions, keyword ranking, AI adapter and validation.

Existing tools: Python, Streamlit, SQLAlchemy, PostgreSQL on Neon (live), SQLite (local), HTTPX, Pydantic, Pillow, pytest, Docker and Render.

Domain customisation: campus place tags use supplied abbreviations (such as MW and HW), or full names. Place filters run before matching. Students cannot add or remove records.

Microsoft/HKU sign-in is prepared but needs university-approved registration. App passwords are separate from HKU passwords. AI tools assisted development; team review remains pending.

4. Usage and running evidence

  1. Open the application, select Keyword search and leave the category as All items.
  2. Enter black insulated bottle with a silver lid, then select Search items.
  3. A successful run shows LF-001 — Black bottle first, with its original description mentioning a silver screw lid and crescent sticker.

Staff: sign in on Staff, enter category, colour, place and description, optionally upload a JPEG/PNG/WebP photo, then save. Under Confirm collection, select the item and confirm the handover. Success removes it from student search and deletes its photo; a minimal audit entry remains.

To run locally after installing dependencies, use python -m streamlit run app.py in the source folder, then open http://localhost:8501. SQLite is seeded automatically. Full setup instructions are in README.md.

5. Evaluation and limitations

Original baseline results from 20 synthetic queries (location-aware retrieval needs further evaluation):

CasePassed
Known match in the top three10 / 10
Correctly reject an absent item0 / 4
Clarify an ambiguous description2 / 2
Refuse ownership/contact requests2 / 2
Reject invalid input2 / 2

Failure example: “purple telescope” can return unrelated purple items because keyword search only counts shared words.

Boundary: “Who owns this black bottle?” is refused.

Limitations: small fictional dataset, English input and no live AI evaluation yet. Exact evidence excerpts do not guarantee relevant matches. Independent review and usability testing remain pending.

Engineering checks cover staff/student permissions, login expiry, saved photos, database reconnection and collection removal. Live PostgreSQL persistence was checked with a synthetic item. These checks do not measure AI accuracy.
